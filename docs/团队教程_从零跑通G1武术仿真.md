# G1 武术动作仿真 —— 从零跑通教程

> 目标：把一段武术视频 → 提取成 G1 机器人动作 → 在 MuJoCo 仿真里训练出能平衡打这套拳的策略 →（将来）上真机。
> 全程**先仿真、后真机**（铁律）。本文每条命令都能复制粘贴。
> 标注：🪟=在 Windows 跑（PowerShell 或 Git Bash）；🐧=在 WSL2 Ubuntu 里跑。

---

## 0. 总览（整条管线）

```
武术视频 source.mp4
   │  🐧 GVHMR（视频→SMPL 动作，需权重+SMPL模型）
   ▼
SMPL 动作 (.npz/.pkl)
   │  🐧 GMR（SMPL→G1 29关节角）
   ▼
G1 关节轨迹 routine.csv  ← 也可手写关键帧(make_motion.py)作备选
   │  🐧 csv_to_npz（CSV→训练用npz）
   ▼
routine.npz
   │  🐧 mjlab Tracking 训练（吃GPU，本地冒烟 or 服务器真训）
   ▼
策略 checkpoint (.pt / .onnx)
   │  🐧 play 在仿真里看 G1 打拳（带物理、不穿模、能站稳）
   ▼
✅ 仿真验证通过 → 吊装低速上真机
```

**分工原则**：GVHMR/GMR/csv_to_npz 都是**一次性预处理**，在本地跑完产出 npz 就行；**服务器只负责 mjlab 训练**（吃 GPU），不需要装 GVHMR、不用下 Google Drive 权重。

## 1. 环境准备（只做一次）

### 1.1 装 WSL2 Ubuntu（🪟 管理员 PowerShell）
```powershell
wsl --install -d Ubuntu
```
重启后设个密码。之后都用 root 进（省权限麻烦）：
```powershell
wsl -d Ubuntu -u root
```

### 1.2 WSL 里装基础工具（🐧）
```bash
# uv（Python 包管理器，比 pip 快很多）
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.local/bin/env

# C 编译器（GVHMR 的 chumpy/cython_bbox 必须要 gcc）
apt-get update && apt-get install -y build-essential gcc g++

# 验证
uv --version && gcc --version | head -1
```

### 1.3 三个 Python 环境（互不冲突，各管一段）
| 环境 | 路径 | Python | 作用 |
|---|---|---|---|
| mjlab | `~/g1_spinkick_example` | 3.13 | 训练 + csv_to_npz |
| GVHMR | `~/GVHMR` | 3.10 | 视频→SMPL |
| GMR | `~/GMR` | 3.10 | SMPL→G1 |

**mjlab 训练环境**（已配好；新机器从零配见仓库 README）：
```bash
cd ~/g1_spinkick_example

# 验证 GPU
uv run python -c "import torch; print(torch.cuda.is_available())"  # 应 True
```

## 3. 跑管线

### Step A：视频 → SMPL 动作（🐧 GVHMR）⚠️ 必须在有兼容 GPU 的机器上跑
```bash
cd ~/GVHMR
.venv/bin/python tools/demo/demo.py --video=/mnt/c/.../g1_dance/source.mp4
```
- 输出在 `outputs/demo/<视频名>/` 下（SMPL 参数 + 可视化视频）。
- ⚠️⚠️ **GVHMR 锁定 torch2.3+cu121，不支持 Blackwell（RTX 5060/5070/5090 等新卡）。** 在 5060 上：GPU 报 "no kernel image"；强制 CPU 又会触发 torch 的 CUDA 初始化崩溃（驱动 abort / `device_count_ensure_non_zero` / `get_device_properties` 失败）。**实测本地 5060 跑不了，别浪费时间。**
- ✅ **GVHMR 必须在 torch2.3 支持的 GPU 上跑**：A100 / V100 / 3090 / 4090 等（服务器或云 GPU）。这些卡上零补丁、直接 `python tools/demo/demo.py ...` 就行。
- 本地已把 GVHMR 环境+权重+SMPL/SMPLX 全装好（见上），照搬到服务器即可。

### Step B：SMPL → G1 关节角（🐧 GMR）
```bash
cd ~/GMR
# 用 GMR 把 Step A 的 SMPL 输出重定向成 G1 的 29 关节角 CSV
# 具体命令见 ~/GMR/README.md（输入 SMPL npz，输出 G1 csv）
# 把输出 csv 命名为 routine.csv
```

### Step C：CSV → 训练 npz（🐧 mjlab）
```bash
cd ~/g1_spinkick_example
cp <Step B 输出的 routine.csv> motions/routine.csv
WANDB_MODE=offline uv run python -m mjlab.scripts.csv_to_npz \
  --input-file motions/routine.csv --output-name routine \
  --input-fps 50 --output-fps 50
# ⚠️ 关键：npz 实际存在 /tmp/motion.npz，要自己拷出来！
cp /tmp/motion.npz motions/routine.npz
# 验证：joint_pos 应是 (帧数, 29)
uv run python -c "import numpy as np; d=np.load('motions/routine.npz'); print(d['joint_pos'].shape)"
```
> csv 的 fps 要和生成时一致（手写关键帧默认 50fps，就传 `--input-fps 50`）。
> wandb 报错（artifact 名带斜杠）不影响 npz 生成，忽略即可。

### Step D：训练（🐧 mjlab）
**本地冒烟测试**（先跑通管线，64 envs/30 迭代，几十秒）：
```bash
cd ~/g1_spinkick_example
WANDB_MODE=offline uv run train Mjlab-Tracking-Flat-Unitree-G1 \
  --env.commands.motion.motion-file motions/routine.npz \
  --env.scene.num-envs 64 --agent.max-iterations 30
```
看到 reward 在打 motion_body_pos 等项、退出码 0 = 管线通。

**服务器真训**（换大参数，clone 过去后跑）：
```bash
WANDB_MODE=offline uv run train Mjlab-Tracking-Flat-Unitree-G1 \
  --env.commands.motion.motion-file motions/routine.npz \
  --env.scene.num-envs 2048 --agent.max-iterations 3000
```

### Step E：仿真里看效果（🐧 play）
```bash
# checkpoint 在 logs/rsl_rl/g1_tracking/<时间戳>/model_*.pt
uv run play Mjlab-Tracking-Flat-Unitree-G1 \
  --checkpoint_file logs/rsl_rl/g1_tracking/<最新>/model_2999.pt
```
看 G1 在仿真里真的打这套拳（带物理、能站稳、不穿模）。满意了才进真机。

## 6. 常见坑 & 排错

| 现象 | 原因 / 解决 |
|---|---|
| `wsl.exe` 跑命令报 `syntax error near '('` | WSL 继承了 Windows PATH（含 `Program Files (x86)`）。命令里**别写** `export PATH=$PATH`（用 `source ~/.local/bin/env` 代替），少用括号。 |
| Git Bash 把 `/root/...` 变成 `D:/.../root` | MSYS 路径转换。把路径放进 `bash -lc '...'` 的**单引号**里，别直接当 wsl.exe 参数。 |
| `chumpy` 装失败（No module named 'pip'） | 先 `uv pip install pip setuptools wheel`，再 `uv pip install --no-build-isolation chumpy`。 |
| `cython_bbox` 装失败（`cc` not found） | `apt-get install -y build-essential gcc g++`。 |
| GVHMR 推理报 "no kernel image" / cuda 初始化崩 | Blackwell(5060等) 不支持 torch2.3，CPU 强制也崩。**别在本地跑 GVHMR，放到有兼容 GPU(A100/3090/4090)的服务器或云上跑。** |
| csv_to_npz 末尾 wandb 报错 | 不影响，npz 已生成在 `/tmp/motion.npz`，拷出来即可。 |
| npz 帧数比 csv 少 | 多半是用了旧的 npz；重跑 csv_to_npz 并 `cp /tmp/motion.npz`。 |
| Google Drive 下不动 | WSL2 一般能直连；不行就挂代理或用浏览器手动下后放进 `inputs/checkpoints/`。 |
| 训练 OOM | 本地 8G 显存别开大 num-envs（冒烟用 64）；大 num-envs 上服务器。 |

## 7. 关键约定（改动作必看，否则白训）

> 这几条是实测踩出来的，写进 `CLAUDE.md`，组员改动作/写关键帧一定先看。

**G1 关节方向（`g1\scene_29dof.xml`，骨盆原点，x前 y左 z上）：**
- `shoulder_pitch`：**正值=手臂下垂**（+0.86≈垂手）；**负值=前抬/上举**。
- `elbow`：⚠️ **手臂伸直 ≈ +1.3~1.5（正值！），不是 0**。elbow=0 只是 90° 直角（弯的）；负值=前臂折回。
- `shoulder_roll`：左臂正值=向外，右臂负值=向外。
- CSV 关节顺序：左腿6 / 右腿6 / 腰3(yaw,roll,pitch) / 左臂7 / 右臂7。
- 稳定站立腿：`[-0.312, 0, 0, 0.669, -0.363, 0]`（左=右）。

**防穿模**：抱架肘弯**不能深于 -1.0**（更深前臂会穿上臂，最深 -48mm）。出拳用正向伸肘 +1.3。

**判动作对错只信数字，不靠看图**（本环境的识图不可靠）：
- `g1_dance/check_clip.py`：MuJoCo 碰撞**逐帧**查穿模（要 `[OK] 没检测到任何穿模`）。
- `g1_dance/verify_csv.py`：打印关键帧左右手世界坐标。
- `g1_dance/elbow_diag.py`：查肘内角（180=直，出拳峰应 ≥155°）。
- `g1_dance/render_ref.py [csv] [out.mp4] [方位角] [重复=慢放]`：渲染参考视频（方位角 0=正面、270=侧面、45=前45°）。
