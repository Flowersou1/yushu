# G1 Dance Studio 使用教程

面向宇树 **G1 EDU+** 的动作编排、本地仿真与真机部署。  
本教程覆盖：怎么用 Studio 做动作、数据如何对齐官方 SDK、如何导出可独立运行的 `arm_sdk` 播放脚本、以及如何按你们服务器流程上机。

---

## 0. 你先建立一张心智图

```
┌─────────────────────┐     导出 YAML / 真机脚本      ┌──────────────────────┐
│  Windows 本机        │ ──────────────────────────► │  Ubuntu 服务器         │
│  G1 Dance Studio    │                               │  + unitree_sdk2_python │
│  (MuJoCo 仿真编排)   │                               │  + 网线 enp6s0 → G1   │
└─────────────────────┘                               └──────────────────────┘
        ▲                                                      │
        │ 不用 unitree_mujoco 也能编动作                        │ rt/arm_sdk
        │                                                      ▼
        │                                              机器人站立平衡 + 上肢跳舞
```

| 阶段 | 在哪做 | 用什么 |
|------|--------|--------|
| 编动作 / 预览 | Windows | `python app.py`（Dance Studio） |
| 导出数据与脚本 | Windows | 保存 YAML / 导出真机脚本 |
| 连服务器 | 本机 SSH | 见仓库 `connection-guide.md` |
| 真机播放 | Ubuntu 服务器 | 生成的 `*_arm_sdk_player.py enp6s0` |

**第一阶段强烈建议：只做上半身（腰 + 双臂），腿交给机器人内置平衡（Loco）。**  
全身 lowcmd 自控腿部需要吊装和自己写平衡，不要一上来就用。

## 2. 打开 Studio 后你会看到什么

启动后有两个窗口：

1. **控制面板**：时间线、滑块、保存/导出  
2. **MuJoCo 窗口**：G1 三维模型  

启动时默认尝试加载 `dances/demo_punch.yaml`（演示出拳）。

### MuJoCo 窗口快捷键

| 键 | 作用 |
|----|------|
| 空格 | 暂停 / 继续 |
| R | 重播 |
| S | 慢动作 0.2x ↔ 1.0x |

### 推荐勾选（编上半身舞）

- **锁定骨盆(调姿)**：摆造型不倒  
- **仅上半身滑块**：少干扰，避免误编腿  
- 需要看物理时再关锁定 / 开虚拟挂带

## 3. 最快编完一段动作（推荐流程）

### 步骤 A：摆关键帧

1. 拖滑块调到目标造型，看 MuJoCo 是否满意  
2. 填写 **名称**（如 `起势`、`出拳`）  
3. 确认 **自动间隔**（默认 1.0 秒，可改）  
4. 点 **＋ 追加当前姿态**  
5. 重复 1–4，拍 5～15 帧通常够一段 20～30 秒小品  

时间会自动递增，不必再手改一堆 `time: 1.00`。

### 步骤 B：改某一帧

1. 时间线点选该帧  
2. **加载到滑块**  
3. 微调滑块  
4. 可改名称 / 时间  
5. **更新选中帧**  

### 步骤 C：整理时间轴

- **上移 / 下移**：调整顺序（会交换时间）  
- **重排时间(按间隔)**：按当前间隔从 0 均匀铺开  
- **删除**：去掉废帧  

### 步骤 D：预览

1. 点 **▶ 播放动作**  
2. 观察插值是否突变、是否自碰  
3. **⏹ 停止并回到编辑** 继续改  

实用技巧：

- **左臂→右臂镜像 / 右臂→左臂镜像**：对称动作更快  
- **纯运动学预览**：不管重力，只看形状  
- 取消锁定骨盆 + 关挂带：粗看「会不会倒」（真机仍以 arm_sdk + loco 为准）  

### 步骤 E：保存

- **保存 / 另存为** → `dances/*.yaml`  
- 建议文件名英文：`demo_punch.yaml`、`wave_hello.yaml`

## 4. 导出什么？分别干什么用？

| 导出 | 按钮 / 命令 | 用途 |
|------|-------------|------|
| 动作工程 | 保存 YAML | 以后继续在 Studio 打开编辑 |
| 稠密轨迹 | 导出 CSV 轨迹 | 分析、画图、给其它程序读 `q0..q28` |
| 关键帧表 | 导出关键帧表 | 一帧一行，Excel 可看 |
| **真机脚本** | **导出真机脚本** | **官方 arm_sdk 风格独立 .py，上传服务器直接跑** |

命令行导出真机脚本：

```bat
cd g1_dance_studio
python export_player.py --dance dances/demo_punch.yaml
```

默认输出：

```text
exports/demo_punch_arm_sdk_player.py
```

## 5. 导出的真机脚本长什么样（对齐官方）

生成脚本的结构对齐官方示例：

`unitree_sdk2_python/example/g1/high_level/g1_arm7_sdk_dds_example.py`

包含：

| 官方要素 | 生成脚本 |
|----------|----------|
| `G1JointIndex` 0–28 | 有 |
| 话题 `rt/arm_sdk` | 有 |
| 订阅 `rt/lowstate` | 有 |
| `motor_cmd[29].q = 1` 使能 Arm SDK | 有 |
| `kp=60, kd=1.5` | 有 |
| `control_dt_=0.02` | 有 |
| 从当前实测角度 blend 过去 | 有（engage 2s） |
| 结束时权重降到 0 释放 | 有（release 1s） |
| 只控腰 + 双臂 | 有（`ARM_JOINTS`） |
| CRC 校验后 Write | 有 |

运行阶段：

```text
engage（2s 混合到首帧） → play（播完整段） → release（1s 释放 arm_sdk） → done
```

## 6. 从导出到真机（按你们 connection-guide）

以下接口名、IP 以现场为准；示例沿用文档习惯。

### 6.1 本机 SSH 上服务器

```bash
# 服务器显示器上看 ip a，找 10.101.x.x
ssh ubuntu@<serverip>
```

### 6.2 确认机器人有线通

```bash
ping 192.168.123.161
# 或你们文档中的实际机器人 IP
# 服务器有线口常见 192.168.123.99/24，不要给有线口配默认网关
```

### 6.3 上传播放脚本

在 **Windows 本机**（PowerShell / 有 scp 的环境）：

```bash
scp g1_dance_studio/exports/demo_punch_arm_sdk_player.py ^
    ubuntu@<serverip>:~/server/beigongshang/mechdance/
```

（组名按 `connection-guide.md`：`mechdance` / `helloword` / `QKWL` 等。）

### 6.4 在服务器上运行

```bash
cd ~/server/beigongshang/mechdance
# 若 SDK 动态库不在默认路径，按你们环境设置 LD_LIBRARY_PATH
python3 demo_punch_arm_sdk_player.py enp6s0
```

按提示 Enter 后开始：先 2 秒平滑切入 → 播放舞蹈 → 释放 Arm SDK。

### 6.5 通用播放器（不生成独立脚本时）

仓库还提供：

```bash
# 在服务器上，需带上 dances 与依赖包结构
python play_real.py --iface enp6s0 --dance dances/demo_punch.yaml --path arm_sdk
```

独立脚本的优点：动作已嵌入，**只拷一个 .py** 就能跑。

## 7. 和官方资料的对齐关系（必读）

官方参考：

- 文档：[基础运动开发](https://support.unitree.com/home/zh/G1_developer/basic_motion_development)  
- 代码：`unitree_sdk2_python/example/g1/low_level/g1_low_level_example.py`  
- 代码：`.../high_level/g1_arm7_sdk_dds_example.py`  

### 7.1 已对齐

- 电机顺序 = 官方 `G1JointIndex`（0–28）  
- 角度单位 = rad  
- G1 使用 `unitree_hg`（不是 Go2 的 `unitree_go`）  
- Arm SDK 使能位、kp/kd、话题名、控制周期  
- 导出 `motor_q[i]` / CSV `q0..q28` 可直接映射 `motor_cmd[i].q`  

### 7.2 两条真机路径怎么选

| 路径 | 话题 | 控什么 | 何时用 |
|------|------|--------|--------|
| **arm_sdk（推荐编舞）** | `rt/arm_sdk` | 腰 + 双臂 | 站立平衡下的上半身舞蹈 |
| **lowcmd（进阶）** | `rt/lowcmd` | 全身 29 电机 | 自研全身控制；须先 `ReleaseMode`，**吊装** |

Studio 默认导出的是 **arm_sdk** 脚本。  
全身 lowcmd 请用 `play_real.py --path lowcmd`，并严格吊装分级测试。

### 7.3 Studio 仿真 ≠ 真机 PD

MuJoCo 里为了「站得住」可能用较大仿真刚度；**真机只用官方示例的 kp/kd**。  
仿真不倒 ≠ 实机安全。

更细的对照表见同目录：`OFFICIAL_ALIGNMENT.md`。

## 8. 安全清单（真机前逐项勾）

- [ ] 机器人型号确认为 29 DoF（或清楚 23 DoF 无效关节）  
- [ ] 已用官方方式进入可站立 / 可 arm_sdk 的状态  
- [ ] 急停由专人持遥控器  
- [ ] 首次幅度小、速度慢；必要时吊装  
- [ ] 周围清场，人不要站在手臂扫掠范围内  
- [ ] 仿真已反复预览，无剧烈突变  
- [ ] 知道如何停止程序并 `release` arm_sdk（脚本结束会自动释放；异常时急停）  
- [ ] 仿真 Domain / 真机网卡隔离，避免误连

## 10. 常见问题

### Q1：Studio 里腿也在动，真机会动腿吗？

arm_sdk 脚本**只下发腰和双臂**。YAML 里可以带腿部关键帧，但独立 arm_sdk 播放器会忽略腿部电机。  
若要用自定义腿部动作，必须走 lowcmd + 自研平衡，风险高。

### Q2：和 unitree_mujoco 什么关系？

| | unitree_mujoco | Dance Studio |
|--|----------------|--------------|
| 目的 | 底层 DDS Sim2Real | 编排 + 直观预览 |
| 是否要 DDS | 要 | 本地编排不要 |
| 动作时间线 | 无 | 有 |

日常编舞用 Studio；要严格走官方仿真桥再 Sim2Real 时，再用 unitree_mujoco。

### Q3：为什么不建议在 Windows 直接控真机？

官方与课程环境默认 Ubuntu + 指定网卡 + cyclonedds。Windows 上 DDS/网卡绑定更容易踩坑。  
标准路径：**本机编 → 服务器跑**。

### Q4：动作发硬 / 抖动？

- 关键帧时间间隔加大  
- 检查是否有相邻帧角度跳变过大  
- 真机 engage 已有 2s 混合；仍抖可把脚本里 `engage_s` 调大  
- 确认 kp/kd 未被改成仿真那套大刚度  

### Q5：收不到 lowstate / 无响应？

- `ping` 机器人是否通  
- 网卡名是否真是 `enp6s0`（`ip -br addr`）  
- Domain、防火墙、是否指错 Wi-Fi 网卡  
- 参考 `connection-guide.md` 网络章节  

### Q6：想改生成脚本里的增益？

打开 `exports/*_arm_sdk_player.py`，与官方一致的位置：

```python
self.kp = 60.0
self.kd = 1.5
self.control_dt_ = 0.02
```

非必要不要乱改；先问宇树推荐值。

## 12. 推荐第一阶段验收

做一段 **20～30 秒** 上半身动作，满足：

1. Studio 内连续播放多次无异常  
2. YAML 已保存，真机脚本已导出  
3. 服务器 arm_sdk 播放完整通过  
4. 急停与结束释放正常  
5. 留存一次日志/录像  

然后再考虑加步态、音乐节拍或全身动作。
