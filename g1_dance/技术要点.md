## 一、G1 关节方向约定（实测，别猜符号）
模型：`g1/scene_29dof.xml`（29 自由度）。原点在骨盆，**x=前 y=左 z=上**，骨盆站立 z≈0.76。

- **`shoulder_pitch`（肩屈伸）**：
  - **正值 = 手臂下垂/靠身**（+0.86 ≈ 自然下垂，拳到胯）。
  - **负值 = 手臂前抬/上举**（**-0.74 ≈ 正前方水平伸直**＝冲拳位；-2.34 ≈ 笔直朝上）。
- **`elbow`（肘）**：⚠️ **手臂真正伸直 ≈ +1.3~1.5（正值！），不是 0**。
  - `elbow=0` 时肘内角仅 ~90°（弯成直角），不是伸直。
  - 负值 = 前臂折回（内角更小）。
  - 出拳伸直到 **+1.3**（内角~165°，留~15°不锁死）；抱架屈肘用 **-0.7**（内角~59°）。
- **`shoulder_roll`（肩外展）**：左臂正值=向外(左)，右臂负值=向外(右)。出拳 roll 小（±0.15）防肘外翻。
- **`waist_yaw`（腰转）**：负值→左肩靠前（左冲拳用负），正值→右肩靠前（右冲拳用正）。

### CSV 关节顺序（mjlab 格式）
每帧 `[root_x, root_y, root_z, qx, qy, qz, qw, 29关节]`，关节顺序：
左腿6(hip_pitch,hip_roll,hip_yaw,knee,ankle_pitch,ankle_roll) / 右腿6 / 腰3(yaw,roll,pitch) / 左臂7(shoulder_pitch,shoulder_roll,shoulder_yaw,elbow,wrist_roll,wrist_pitch,wrist_yaw) / 右臂7。

稳定站立腿（轻微屈膝、两腿对称）：`[-0.312, 0, 0, 0.669, -0.363, 0]`（左=右）。

### 标准化姿势（左腕世界坐标）
- 抱架：双拳 ≈ (±0.03, ±0.15, **+1.04**) 左右对称在胸前。
- 左冲拳峰：左拳 ≈ (**+0.28**, +0.10, +1.04) 正前方肩高。

## 二、防穿模约束（实测）
- **负向折肘（前臂折回穿上臂）不能深于 -1.0**（-1.3/-1.6/-1.8 穿透 -10~-48mm）。抱架屈肘用 -0.7。
- 出拳用**正向伸肘(+1.3)**，手臂朝外伸、不穿模。
- **每改一版动作必跑 `check_clip.py`** 确认 `[OK] 没检测到任何穿模`。该模型能检测"手臂穿胸"（torso_link 与腕部 link 会报碰撞）。

## 三、验证工具链（纯 Windows mujoco，不用 WSL/wandb）
- `choreographer.py` —— **GUI 动作编辑器**（拖滑块、实时预览、存关键帧、导出 CSV）。组员编动作用。
- `combine_routines.py` —— 多人 CSV 拼成全套（段间自动过渡）。
- `make_motion.py` / `make_motion_test.py` —— 关键帧脚本（纯代码编，备选）。
- `check_clip.py` —— MuJoCo 碰撞**逐帧**查穿模（**判穿模只信它**）。
- `verify_csv.py` —— 打印关键帧左右手世界坐标 + 腰 yaw（判拳位/幅度）。
- `elbow_diag.py` —— 查肘内角（180=直，出拳峰应 ≥155°）。
- `render_ref.py [csv] [out.mp4] [方位角] [重复=慢放]` —— 渲参考视频（方位角 0=正面、270=侧面、45=前45°）。

## 四、关键发现：反应式平衡器撑不住"大幅前伸手臂"
- 实测一套含踝+髋+腰+前馈的平衡控制器（g1-mechdance）：**蹲起（垂直动作）能稳住**，但**向前出手（拳法冲拳）会让机器人前趴摔倒**（pitch 35°）。
- 调大补偿增益 → 改往后仰摔（过补偿）。**调小→前趴、调大→后仰，无中间值**。
- 结论：**大幅前伸动作的重心扰动超出了这类反应式平衡器的补偿极限**。要自平衡打拳，**得走 RL**（学主动挪重心），或**吊装**（绳兜住、不靠平衡）。

## 五、RL 训练（mjlab）要点
- **管线**：routine.csv → `csv_to_npz` 转 npz → `Mjlab-Tracking-Flat-Unitree-G1` 训练 → play 仿真验证。
- **csv_to_npz 坑**：①末尾 wandb 报错（artifact 名带斜杠）不影响，npz 已生成在 `/tmp/motion.npz`，**要自己 cp 出来**；②输入 fps 要和生成时一致（关键帧默认 50fps 就传 `--input-fps 50`）。
- **GPU 要求**：24G 显存起（RTX 3090/4090、A10、A100）。8G 卡（如 RTX 5060）能跑但 envs 少、收敛慢。拳法训练 ~1-3h（3090），全套更长。
- ⚠️ **Blackwell（RTX 50 系）注意**：mjlab 用 torch2.9+cu128 支持 Blackwell（能跑）；但 GVHMR 锁的 torch2.3 不支持（见下）。

---

## 六、GVHMR（视频→SMPL 动作）环境坑
- GVHMR 锁 **torch 2.3+cu121**，**不支持 Blackwell（RTX 50 系，sm_120）**——GPU 报 "no kernel image"；强制 CPU 会触发 torch CUDA 初始化崩。**GVHMR 必须在有兼容 GPU（A100/3090/4090 等）的机器上跑。**
- 装 GVHMR：`chumpy` 要先 `uv pip install pip setuptools wheel` 再 `--no-build-isolation`；`cython_bbox` 要 `apt install build-essential gcc g++`。
- GVHMR 权重用 gdown 从 Google Drive 下，会**多套一层 `checkpoints/checkpoints/`**，要 `mv` 上移一级。
- GVHMR 需要 **SMPL + SMPLX 模型**（注册下载，禁止再分发）。

## 七、铁律
1. **一切动作先仿真跑通才能上真机**。
2. 真机首次**必须吊装**、低速（首速 10–20%、幅度 20–30%）。
3. 每改一版动作，先 `check_clip.py` 查穿模，再考虑训练/上机。
